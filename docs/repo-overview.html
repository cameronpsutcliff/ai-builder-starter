Personal Brand & AI Builder Starter

A browser-first portfolio with an interactive lab and a guided path from idea to deployment.

Repository README

Purpose & Data Scope

  • Site owners use the starter to publish their story, projects, and first interactive app.
  • Visitors browse public profiles and project pages, then try tools in their browser.
  • Treat all bundled content and demo inputs as public. Use cleared or sample data.

Architecture & Consumers

Vite bundles React routes and the local Abyssal theme package. The site requests Google Fonts and can link to owner-selected destinations. Route map

Environments, Scale & Cost Controls

Local
npm run dev serves a hot-reloading preview on port 5173 by default.
CI
Node 22 checks pull requests and pushes to main with a clean install and build. Build workflow
UAT and production
Use a static-host preview for acceptance and promote it to the owner’s domain. Hosting is configured per copy.
Volume and spend
Release on demand. Static requests use host bandwidth and lab computation runs in the browser.
Token use
The starter makes zero model calls. Owners manage AI usage in their chosen coding agent.

Data Contracts, Auth & Dependencies

  • Vite emits static HTML, scripts, and assets in dist/. There is no service API.
  • Every project needs a unique slug. Its optional interactiveId must match a registry key to display a tool. Project schema
  • The site has no sign-in or server-side secrets. All browser assets are public.
  • Node, the committed lockfile, and the in-repo theme package cover build dependencies. No private laptop paths are required. Package manifest

Repo-Specific SDLC & Release Pipeline

  1. Align. Agree on a visitor action and an observable result.
  2. Small slice. Make one usable flow on a topic branch and open a pull request.
  3. Build and verify. Run npm run build and smoke-test the project URL. Baseline automated test count is zero. CI checks install, types, and bundling. An independent reviewer from another model family checks the release evidence before promotion.
  4. Ship. Merge a passing change, verify the static-host preview, then promote with owner approval. Roll back by restoring the last good deployment.

The repository defines the build check. Branch protection and deployment automation are configured by the owner. SDLC playbook

Key Decisions (ADRs) & Stack Fit

  • React and TypeScript fit small interactive tools with typed profile and project data.
  • Vite provides hot reload for co-building and a static output for simple hosting.
  • The component registry lets each project opt into a lab while keeping metadata as plain data.
  • These decisions live in the agent playbook. The repository currently has zero formal ADRs. Agent playbook

Known Limits & Active Debt

  • Host rewrites are required for direct visits to client-side routes such as /work/:slug.
  • Profile and project edits require a rebuild. The starter has no CMS, accounts, or shared data store.
  • CI has no automated browser tests. Changes to lab behavior need a manual smoke test.
